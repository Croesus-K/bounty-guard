# 《我给自己造了个 AI 代码安全审查器》—— 发文草稿

> 状态：草稿（数据截至 2026-08-31，发布前请核对最终数字）
> 目标平台：掘金 / HelloGitHub；配图：靶场 PR 截图、报告截图、demo GIF

## 开头：一个让我耿耿于怀的提示

去年我做「赏金契约」（一个契约管理系统）的时候，修完 XSS 提交，安全扫描器给了我一巴掌：
`Math.random` 被用在了生成令牌的场景，弱随机。

提示是对的。但让我耿耿于怀的是另一件事：**为什么这行代码是我写完很久之后才被工具发现的？**
如果在我提交它的那一刻，就有一只手拍在我肩膀上说"这行有问题"，后面的修复成本几乎是零。

于是我造了 bounty-guard：一个 GitHub Action + CLI 双形态的代码安全审查器。
规则引擎初筛 diff 里的安全问题 → LLM 复核降噪 → 结果以 PR 评论呈现。

## 三个设计决策（也是面试讲稿）

### 1. 只审新增行

全量扫描是过去时。diff 是审查的自然单位：PR 里改了什么，就审什么。
bounty-guard 的 diff 解析器以 hunk 头声明的行数为界切分正文，
新增行的行号精确到行——这是"守住每一行 diff"的字面含义，也是成本控制的根基。

### 2. LLM 永远只复核、不发明

LLM 幻觉是很多人不敢把大模型接进质量工具的原因。我的解法是把 LLM 的权限收到最小：

- 输入永远是规则已命中的告警（规则 ID、初判严重度、命中行、上下文窗口）；
- 输出只有三个结论：确认 / 误报 / 不确定；
- 严重度**只允许下调**——提示词禁止、解析层丢弃上调建议、流水线双保险；
- 复核失败的兜底不是报错，是 `unsure` 保留规则原判。

LLM 在这个架构里是"降噪器"，不是"探测器"。误报被它过滤，漏报它不背锅。

### 3. 无 Key 优雅降级

没配 API Key？整条流水线照跑，只是少了复核环节。CI 里零成本、零配置。
工具不应该因为一个可选增强不可用而不可用。

## 误报治理：被自己的工具打脸三次

这部分是我最想讲的。开发过程中，我桌面上另一个安全扫描器（Mimosa）把我拦了三次：

1. Week 0：测试数据里出现动态执行调用的**字符串字面量**（从未执行）→ 被拦；
2. Week 1：diff 解析器用正则的 exec 方法做匹配 → 被判"命令注入"拦截两次，
   最后换成语义等价的 match/test；
3. Week 1：测试样例里的**假密钥**被当作真实泄露拦截——而我的
   hardcoded-secret 规则的判定逻辑和它一模一样。假凭据与真威胁同形，
   这是形态匹配的宿命。

这些案例全部记进了项目的素材库。结论一句话：**形态匹配无法区分"真实威胁、检测代码、测试样例"**，
所以纯规则的扫描器需要一层能理解上下文的复核者。这不是 LLM 焦虑，是工程需要。

## 数据说话

- 回滚验证：把「赏金契约」checkout 到修复 XSS 之前的版本生成 diff（129 新增行），
  bounty-guard 命中当年那个存储型 XSS（`index.html:524`），0 误报。
- 靶场：故意引入 3 个问题的 PR，Action 3/3 精准命中（XSS 高危、MD5 存密码高危、明文 http 低危），
  `--fail-on high` 门禁红灯，评论由 bot 发布且重复扫描只更新不刷屏。
- 误报率实测：express / axios / vite 各取 3 个近期真实 PR，共 9 PR / 1183 行新增，
  规则引擎命中 4 条——全部是 plain-http 低危、全部在测试文件里。
  翻译一下：**真实业务代码零误报**；测试文件里的 http 样例 URL 是唯一噪声，
  而 LLM 复核的提示词里明确"测试文件判 false-positive"，正是为了吃掉这类噪声。

## 技术栈与规模

TypeScript strict / ESM / Vitest / 零运行时依赖（除了 commander）。
Node 自带 fetch 完成 LLM 与 GitHub API 调用；diff 解析、glob 匹配全部手写。
93 项测试。四周四个提交批次，每个都有中文 conventional commit。

## 结尾：给你的Action 也装一只手

仓库：github.com/Croesus-K/bounty-guard（含完整设计文档 docs/PLAN.md）。
两个 workflow 步骤接入，无 Key 也能跑。如果你的团队也有"代码提交了才想起安全"的时刻，
欢迎试试、提 issue、一起调规则。

下一个版本（v0.2）计划：AST 分析替代纯正则、多语言支持。
